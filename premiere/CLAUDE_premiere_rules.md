# Premiere Pro 自動編集ルール（premiere MCP を使うときは必ず守る）

## 大原則：元の動画・元のシーケンスは使わない。コピーだけを編集する
- 元の素材ファイル（例: `IMG_9671.MOV`）と元のシーケンス（例: `IMG_9671`）は**読み取り専用**。編集・移動・名前変更・削除をしない。
- 編集してよいのは、素材のコピー（`〇〇 のコピー.MOV`）から作った **`〇〇 のコピー` シーケンス**だけ。

## 作業場所：外付けドライブ ELECOM（Mac 本体は容量不足のため使わない）
- 作業フォルダ: `/Volumes/ELECOM/Premiere作業/`
  - 素材のコピー → `/Volumes/ELECOM/Premiere作業/コピー素材/`
  - YouTube用の書き出し → `/Volumes/ELECOM/Premiere作業/YouTube書き出し/`
- 最初に `ls /Volumes/ELECOM` で ELECOM がつながっているか確かめる。**つながっていなければ何もせず止まり**、「ELECOM をつないでください」と伝える。Mac 本体やほかのドライブに代わりに保存しない。
- 作業前に `df -h /Volumes/ELECOM` で空きを確認し、（素材サイズ＋書き出し見込み）より少なければ止まって報告する。

編集を頼まれたら、必ず **1 コピー → 2 自動編集 → 3 確認 → 4 YouTube用に書き出し** の順で、できるだけユーザーに手作業をさせずに進める。
各段階の終わりに「1 完了」「2 完了」のように一言報告してから次へ進む。

---

## 1. 最初にコピーする
1. `ping` で接続を確認し、`get_project_info` / `list_sequences` などでプロジェクト名・アクティブシーケンス・素材ファイルのパスを調べる。
2. `/Volumes/ELECOM/Premiere作業/コピー素材/〇〇 のコピー.拡張子` を作る（フォルダが無ければ `mkdir -p`）。
   - Bash で `cp -n "元のパス" "コピーのパス"` を使う（`-n` で上書きしない）。
   - 既にある場合は、サイズが元ファイルと同じときだけ使う。違えば途中で止まった壊れたコピーなので、削除の承認を取ってから作り直す。
   - 別ドライブへのコピーは時間がかかる（数GBで数分）ことを先に伝える。
   - 元ファイルに `mv`・`rm`・上書きをしない。
3. 元ファイルの `ls -l`（サイズ・更新日時）を控える（手順3で比較する）。
4. `import_media` でコピーを読み込み、`create_sequence_from_clips` で `〇〇 のコピー` シーケンスを作って開く（既にあれば再利用）。
   - `import_media` は `filesystem` 権限が必要。権限が無い場合は、ユーザーに「Premiere で ⌘I → `〇〇 のコピー.MOV` を読み込んでください」と頼み、読み込み後に続ける。
5. アクティブシーケンス名が「のコピー」で終わり、クリップがすべてコピー素材を参照していることを確認する。満たさなければ**ここで止まって報告**し、編集に進まない。
6. 編集前のコピーシーケンスの状態を `get_sequence_structure` で控える（手順3で比較する）。

## 2. 自動編集する
1. 依頼内容を、どのツールで・どこを・どう変えるか日本語で短く示し、そのまま実行する。
   - ユーザーが「確認してから」「計画だけ」と言った場合だけ、「実行して」と言われるまで待つ。
2. 対象は `〇〇 のコピー` シーケンスだけ。依頼されていない編集を勝手に追加しない。
3. 途中で迷う判断や、登録されていない権限（特に `unsafe-script`）が必要になったら、**勝手に進めず**止まって理由を説明し、承認を待つ。
4. 無音検出などで FFmpeg（`ffprobe`）が無いと言われたら、`brew install ffmpeg` を提案して承認を待つ（勝手に入れない）。

## 3. 確認する
1. **Claude の自動チェック**（読み取りのみ）を行い、結果を ✅ / ❌ の一覧で報告する。
   - コピーシーケンス: `get_sequence_structure` で編集前と比べ、依頼どおりに変わったか（カット数・長さ・追加したもの）。`audit_timeline_health` で問題がないか。
   - 元シーケンス: `IMG_9671` など元のシーケンスが変わっていないか。
   - 元ファイル: `ls -l` のサイズ・更新日時が手順1-3 の控えと同じか。
2. **ユーザーに確認を頼む**: Premiere でコピーシーケンスを再生して見てもらう。見るべき箇所（変更した時間位置）を一覧で示す。
3. ユーザーが OK なら ⌘S での保存を促す。NG なら ⌘Z で戻すか、指摘どおりに手順2からやり直す。
4. ❌ が1つでもあれば、保存を促さずに原因を報告する。
5. **ユーザーが「OK」と言うまで手順4に進まない**（書き出しは時間がかかるため）。

## 4. YouTube用に書き出す（確認で OK が出た後だけ）
1. 書き出すのは `〇〇 のコピー` シーケンスだけ。元のシーケンスは書き出さない。
2. 形式は YouTube 推奨の **MP4（H.264 映像 + AAC 音声）**。
   - 解像度・フレームレート・縦横の向きはシーケンス（素材）に合わせる。Premiere の書き出しプリセット「YouTube」系、または H.264「ソースの一致 - 高速ビットレート」を使う。
   - 縦長で60秒以内なら YouTube ショートとしてそのまま使えることを伝える。
3. 保存先は `/Volumes/ELECOM/Premiere作業/YouTube書き出し/`、ファイル名は `〇〇_YouTube_YYYYMMDD.mp4`。
   - 同じ名前のファイルがあれば上書きせず、末尾に `_2`, `_3` を付ける。フォルダが無ければ Bash の `mkdir -p` で作る。
4. `export_sequence` で書き出す（`export` 権限が必要）。書き出し中は Premiere を操作しないようユーザーに伝える。
5. 書き出し後に確認して報告する:
   - Bash の `ls -l` でファイルができていて 0 バイトでないこと
   - 可能なら `verify_delivery_file`（`filesystem` 権限）で H.264 / AAC / 解像度 / 長さを確認
   - 保存場所を伝え、Finder で開く（`open /Volumes/ELECOM/Premiere作業/YouTube書き出し/`）
6. YouTube へのアップロードは**しない**。アップロードはユーザーが YouTube Studio で行う。

---

## 守ること
- 使ってよい権限は MCP に登録された範囲だけ。足りない場合は勝手に追加せず、理由を説明して承認を待つ。
- Bash で行ってよいのは: 素材のコピー（`cp -n`）、`/Volumes/ELECOM/Premiere作業/` 内のフォルダ作成（`mkdir -p`）、確認用の `ls -l`・`df -h` と `open`。それ以外（削除・移動・インストール等）は承認を取る。
- `~/.claude/` の設定や MCP の登録内容は変更しない。
